# 原生 SWE-smith GRPO：真实固定批诊断与评分修复（2026-10-18）

本次记录区分真实模型更新、评分工程验收和验证集收益。正式训练仍使用原生 Smith 四卡 GRPO；训练核心保持原不可变版本。本仓库已有 CPU 目标函数合同工具，以下真实 GPU 实验的完整通用实现尚未发布，不能将本文视为可复现代码包验收。

## 真实固定批拟合已通过窄验收

从正式检查点冻结两条完整、已批准的 rollout，共 8,626 个动作 token，其中正 Advantage 3,430 个、负 Advantage 5,196 个。固定 token ID、mask、Advantage、旧策略及参考 logprob，使用原生 SP4、静态 microbatch=1 路径；没有重新采集答案。

独立诊断完成 16 次更新，耗时约 60.79 秒。四个 rank 的实际 optimizer param_groups 学习率均为 2e-7；128 次真实损失边界校验确认旧 logprob 和 Advantage 指纹一致。冻结文件未变化，各 rank 每次更新的小量参数采样 delta 均非零。

- Policy loss：0.01454163 → 0.01341248。
- 正 Advantage 动作平均 logprob 变化：+0.02783203；负 Advantage：−0.11132813。
- 梯度有限，实测裁剪前范数范围 0.02016–0.05352，低于阈值 1；实测裁剪后相同。
- 旧策略近似 KL 为 0.01867676，PPO clip fraction 为 0.133255；后者不是长度截断率。

这只证明该固定小批在固定旧策略输入下能够产生预期更新方向，不证明新 rollout 的探索、信用分配或验证集泛化。实验权重未保存为正式检查点、未推送到正式推理，诊断步骤和计时未混入正式训练或探针。

首次诊断曾因 worker setup hook 覆盖原生 loss 注册而在更新前失败；另一次因重复休眠推理副本失败。这些是工程故障，不是模型不收敛。第一次完成 16 次更新的结果也未纳入固定旧策略验收：原生单 minibatch、单 epoch 快捷路径采用当前 logprob.detach 作为旧值。随后仅在独立诊断中显式启用 rollout logprob，并在实际损失边界逐批校验，才接受本次结果；这不等于证明正式单次 GRPO 更新错误。

## 评分工程：实际轨迹验收与剩余限制

四道 Go 任务原先缺少 Python 启动运行时。只读最小 Python 标准库、SSL 和原生 Go 运行时经实际目标镜像及 Kubernetes 验证后，四条真实模型提交均完成评分、独立原始 JSON 事件/SHA 校验及归档奖励核对，结果为两题通过、两题失败。没有回填历史缺失奖励。

Go 使用独立 go-structured-v1 协议；P2P 为 all_requested，与 pytest 同文件范围不同，不能冒充统一协议下的全量基线比较。首次 Kubernetes Job 虽然 Complete，但启动 shell 重置 PATH 导致评分失败；只有修正 PATH 后评分报告、门禁和奖励全部一致才算验收。

另修复了被测 exceptiongroup 格式化器异常导致 pytest 报告生成中断的问题。仅在真实测试已有异常、且二次异常来自指定格式化器时记录真实 failed 报告并继续；正常、skip 及无关插件异常保持原语义。实际目标镜像、原模型补丁、同一 89 项测试和 120 秒预算下完成执行，F2P 通过 62/84，真实奖励为 0，独立门禁通过。该评分版本已采用；线上实际触发此 fallback 仍需单独证据。

用户保留严格评分规则：语法、导入、编译失败和测试超时继续单列不可评分，不补零，不增加单测超时规则，也不扩大 120 秒评分预算。环境、runner 或事件工程故障仍须修复，不能一概归因模型。
